0.1  YOUR .env EDIT BLOCKER HAS NEVER BLOCKED ANYTHING
------------------------------------------------------

.claude/settings.json line 25:

    echo "$CLAUDE_TOOL_INPUT" | grep -qE '(^|/)\.env$' \
      && echo 'BLOCKED: ...' >&2 && exit 2 || exit 0

Two independent fatal bugs:

  1. CLAUDE_TOOL_INPUT is not a thing.
     The hooks reference lists exactly these env vars for command hooks:
         $CLAUDE_PROJECT_DIR
         $CLAUDE_PLUGIN_ROOT
         $CLAUDE_PLUGIN_DATA
         $CLAUDE_CODE_REMOTE
         $CLAUDE_CODE_BRIDGE_SESSION_ID
         $CLAUDE_EFFORT
     Tool input arrives as JSON on STDIN, never as an env var.
     So `echo ""` -> grep finds nothing -> `|| exit 0`.

  2. Even if the var existed, the regex could never match.
     `(^|/)\.env$` is anchored to end-of-line, and a JSON payload ends
     in `}`, not `.env`.

Tested directly (rather than by editing .env):

    TEST 1 (var unset):                        exit 0 (allowed)
    TEST 2 (var set to realistic payload JSON): exit 0 (allowed)

You have been relying on a guard that is a no-op.


0.2  ALL THREE PostToolUse HOOKS TALK TO A CHANNEL CLAUDE CANNOT HEAR
----------------------------------------------------------------------

The hooks reference has an explicit routing table. For PostToolUse:

    Output channel            Reaches you   Reaches Claude
    ----------------------    -----------   --------------
    plain stdout, exit 0      NO (debug     NO
                              log only)
    systemMessage             YES           NO
    additionalContext         YES           YES
    exit 2 + stderr           YES           YES

Against your config:

  * `git status --short`
    Plain stdout, exit 0. Goes to the debug log.
    Neither you nor Claude sees it. Completely dead.

  * agents/windows restart reminder
    Emits systemMessage. YOU see the warning; CLAUDE DOES NOT.

    that a restart is needed, and cheerfully reports the fix as done.
    This hook was built to solve your #1 pain point and is wired to the
    one channel that cannot solve it.

  * ruff_check.py
    Emits systemMessage. Same problem: ruff findings reach you, not the
    model that could fix them.
    (Mechanics are otherwise fine - confirmed `python3 -m ruff` resolves
    to ruff 0.8.4 in your Git Bash. Note `python -m ruff` does NOT; the
    hook is correct to use python3.)

Secondary issue:
    The reminder greps `agents[\\/]+windows` against the ENTIRE stdin
    payload, which includes the file CONTENT being written. Any file whose
    text mentions "agents/windows" - including CLAUDE.md - false-positives.

Also: the docs place systemMessage inside `hookSpecificOutput`, not at top
level as you have it. Move it when you rewrite.

[**4]  A STOP HOOK - THE "REPORTED DONE BUT NOT APPLIED" FIX   -- 45 minutes
---------------------------------------------------------------------------

This is the feature you're missing that targets your stated problem most
precisely.

Stop fires when Claude finishes responding and is a BLOCKING event: exit 2
prevents the stop, and the stderr reason IS shown to Claude, which then
keeps working. That converts "I manually read git diff to verify every
change" into a machine check.

.claude/hooks/verify_applied.py:

    import hashlib, json, os, subprocess, sys

    data = json.load(sys.stdin)
    session = data.get("session_id", "nosession")
    root = os.environ.get("CLAUDE_PROJECT_DIR", ".")

    diff = subprocess.run(["git", "-C", root, "diff", "HEAD"],
                          capture_output=True, text=True).stdout
    if not diff.strip():
        sys.exit(0)          # nothing changed; nothing to verify

    # Only nag once per distinct working-tree state, so we never loop forever.
    stamp = os.path.join(os.environ.get("TEMP", "/tmp"),
                         f"itdeck-verify-{session}")
    digest = hashlib.sha1(diff.encode()).hexdigest()
    if os.path.exists(stamp) and open(stamp).read().strip() == digest:
        sys.exit(0)
    open(stamp, "w").write(digest)

    stat = subprocess.run(["git", "-C", root, "diff", "--stat", "HEAD"],
                          capture_output=True, text=True).stdout

    print(
        "VERIFY BEFORE STOPPING. This is the actual working tree vs HEAD:\n\n"
        f"{stat}\n"
        "Check every change you just claimed to make against this diff. If "
        "something you reported is missing or only partially applied, apply it "
        "now. If a file under agents/windows/ appears above, the running agent "
        "has NOT picked it up unless you invoked restart-windows-agent this "
        "session. When everything matches, say so in one line and stop.",
        file=sys.stderr,
    )
    sys.exit(2)

Register it in .claude/settings.json:

    "Stop": [
      { "hooks": [
          { "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/verify_applied.py\"" }
      ]}
    ]

The digest stamp is the loop guard: once Claude has been shown a given diff
state, that same state won't block again. If Claude FIXES something, the
diff changes, and it gets one more verification pass - which is what you
want.

HONEST CAVEAT: a hook cannot know what Claude CLAIMED, only what's on disk.
This doesn't catch a fabricated claim in the abstract; it forces a mandatory
read of ground truth before the turn can end, which is where these failures
actually get caught. Worth it for a 45-minute build given how many hours the
failure mode has cost you.

[*6]  PLAN MODE - FREE, ADOPT TODAY
---------------------------------------------------------------------------

Press SHIFT+TAB to cycle into it, or prefix one prompt with /plan, or start
with `claude --permission-mode plan`.

Claude reads files and runs exploratory shell commands but CANNOT EDIT YOUR
SOURCE until you approve the plan. Approving presents three options
(auto mode / manually approve each edit / keep planning). Ctrl+G opens the
proposed plan in your editor so you can edit it before Claude proceeds.

For you specifically: use it for anything touching the message shape between
client -> backend -> agent, where CLAUDE.md warns not to assume today's
execute-only shape covers a new case. Catching a wrong plan is much cheaper
than catching it after a deploy across three machines.

You can make it the default per-project with:

    "permissions": { "defaultMode": "plan" }

in .claude/settings.json. I'd try it manually for a week first - as a
default it gets tiresome for one-line fixes.


[*7]  CHECKPOINTING / /rewind - FREE, ALREADY ON

Automatic. Claude Code snapshots file state before each of your prompts

Open it with /rewind or DOUBLE-ESC on an empty prompt. You can restore code,

[*8]  A SessionStart HOOK THAT HANDS CLAUDE THE REAL STATE     -- 20 minutes
---------------------------------------------------------------------------

SessionStart fires when a session begins or resumes. Per the routing table,
its plain stdout goes to YOU but additionalContext goes to CLAUDE. So emit
JSON:

    import json, subprocess, os

    root = os.environ.get("CLAUDE_PROJECT_DIR", ".")
    def g(*a): return subprocess.run(["git", "-C", root, *a],
                                     capture_output=True, text=True).stdout.strip()

    lines = [
        f"HEAD: {g('log', '-1', '--oneline')}",
        f"Uncommitted: {g('status', '--short') or 'clean'}",
        f"Unpushed: {g('log', 'origin/main..HEAD', '--oneline') or 'none'}",
    ]
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "SessionStart",
        "additionalContext": "IT-Deck state at session start:\n" + "\n".join(lines),
    }}))

Every session then opens with Claude knowing whether you have unpushed work
- instead of discovering it three steps into a debugging session.
